# ステージ生成・検証ツール

`levels.js` は手書きではなく、ここのスクリプトで生成・検証しています。

## 1. 候補プールを作る（数分かかります）

```sh
python3 generate-pool.py pool.json
```

**正解の経路を先に引き、止めたい位置にお邪魔ブロックを置いていく逆算方式**で盤面を作ります
（`carve()`）。各手で「行けるところまで」ではなく途中で止めたい場合、その一つ先にブロックを
新設して停止理由を作ります。経路が通らなかったマスも最後にブロックへ変換します。
経路上でも停止理由でもないマスなので、変換しても経路は変わりません。

ランダムにブロックを置く方式も試しましたが、解ける盤面がほぼブロック0〜1個のものに偏り
（7x7で成功例の平均1.1個）、盤面がスカスカになるため採用していません。

作った盤面は改めて全解探索にかけ、難易度指標（マス数・ブロック数・迷いどころの数・
探索ノード数・解の総数）を記録します。数十秒で10万件規模のプールができます。

環境変数: `PER_SIZE`（盤面サイズごとの上限件数）、`BUDGET_SCALE`（時間予算の倍率）、
`P_LO`/`P_HI`（早期停止の確率＝ブロックの作られやすさ）。

## 2. 50ステージを選んで levels.js を書き出す

```sh
python3 build-levels.py pool.json ../levels.js
```

難易度スコアがなだらかに上がるよう50件を選びます。一本道の盤面とブロックが少なすぎる盤面は
候補から除き、終盤は迷いどころが3つ以上ある盤面だけを使います。書き出す前に全件を再生検証します
（新ルールで手順を再生して全マスが塗られるか、空振りの手が混ざっていないか、
盤面が連結しているか）。

## 3. ブラウザで通しテストする

```sh
# リポジトリのルートで
python3 -m http.server 8777 --bind 127.0.0.1 &
node tools/test.mjs      # 要 playwright
```

登録不要で始められること、全50ステージの自動クリア、オートセーブと再開、
各ボタンの動作と配置、クリア後の再チャレンジ、★が黄色の塗りつぶしであること、
通過済みマスに戻れないこと、スワイプ操作、全ステージにお邪魔ブロックがあること、
アイコンが単色かどうかを確認します。

## 4. 1ファイルにまとめて配布する

```sh
python3 build-single-file.py out.html --standalone   # 単体で開ける完全なHTML
python3 build-single-file.py out.html                # head を配布先が用意する形式（本文のみ）
```

CSS と JS をすべて埋め込むので、1枚のHTMLだけを置ける場所にそのまま配布できます。
